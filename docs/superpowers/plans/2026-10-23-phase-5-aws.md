# Phase 5: AWS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same Helm chart runs on EKS in us-east-2 and comes up with `make aws-up`. `make aws-down` dumps Postgres to S3, checks the dump, and tears down everything that bills by the hour.

**Architecture:**
- Two Terraform stacks under `infra/`:
  - `base` is kept: the dump bucket, ECR, the ACM certificate, GitHub's push role, and the budget.
  - `cluster` is created and destroyed on demand: VPC, EKS, three t3.large nodes, an NLB, and a Cloudflare record.
- The NLB ends TLS and sends proxy protocol to Traefik's NodePorts. Traefik routes to the gateway exactly as on k3d.
- Shell scripts behind `make aws-*` drive Terraform, Helm, and kubectl.
- Postgres is restored on first boot by an init container plus a startup script.

**Tech Stack:**
- Terraform with `hashicorp/aws`, `cloudflare/cloudflare` v5, `terraform-aws-modules/vpc`, `terraform-aws-modules/eks`, and `terraform-aws-modules/eks-pod-identity`
- AWS CLI v2
- EKS 1.35 with the VPC CNI (network policy on), the EBS CSI driver, and the Pod Identity agent
- Traefik's Helm chart and Strimzi 1.2.0
- GitHub Actions OIDC, then ECR
- The existing chart, Java 17, JUnit 5

**Spec:** `docs/superpowers/specs/2026-10-22-phase-5-aws-design.md`. Read it first: this plan only adds the decisions the spec leaves open.

## Global Constraints

- Region `us-east-2`. Every resource is tagged `project = sports-notifier` (provider `default_tags`). Cluster name `sports-notifier`.
- EKS `1.35`. Node group: 3 × `t3.large`, min, max, and desired all 3, AL2023, one subnet per zone.
- VPC `10.40.0.0/16`, three public subnets, **no NAT gateway**. The API endpoint is public, open only to `<your ip>/32`.
- NodePorts: Traefik `web` on 30080 and `websecure` on 30443. The NLB listens on 80/TCP → 30080 and 443/TLS → 30443, with policy `ELBSecurityPolicy-TLS13-1-2-2021-06`. Proxy protocol v2 on, client IP preservation off.
- Hostname `sports.<domain>`. The Cloudflare record is DNS only (`proxied = false`), TTL 60.
- Kafka on AWS: 3 nodes, RF 3, `min.insync.replicas` 2, 10 Gi each, one per zone, `rack.topologyKey: topology.kubernetes.io/zone`. Postgres 10 Gi, Redis 1 Gi.
- Dump: `s3://<dump bucket>/dumps/latest.dump`. Versioned; old versions expire after 30 days.
- ECR repo `sports-notifier`: tags mutable, keep the last 20, scan on push. Image tags:
  - `<short sha>` on a push to main
  - `pr<N>-<short head sha>` and `pr<N>` on a pull request
- Budget: $25/month; alerts at 40% and 100% actual and 100% forecast.
- kubectl context for AWS: `sports-notifier-aws`. Every AWS command passes it explicitly. The k3d context is never touched.
- No long-lived AWS keys anywhere: SSO profile `sports` on the Mac, OIDC in CI. The Cloudflare token lives in the macOS keychain, service `sports-notifier-cloudflare`.
- The user runs every `terraform apply` and `destroy` and reads the plan first. Never pass `-auto-approve` in a script the user runs.
- Pin every version: Terraform `required_version`, providers, modules, Helm charts, and images. Pin the current release at the time the task runs and write the number in the file.
- KEDA is not in this phase.

## Review Focus

1. **A missing or broken dump must never cause data loss.**
   - `aws-down` must not destroy anything if the dump fails, is empty, or has zero users.
   - The restore must never quietly start empty when S3 answered with an error other than "not found".
   - Tests: Task 8 (fake-CLI tests), Task 9 (in-cluster checks).
2. **A restore that fails partway must not leave an empty, initialized database** that later starts as if it were fine. Test: Task 9, the corrupt-dump check.
3. **A Postgres restart while the cluster is up must not refetch or restore over live data.** Test: Task 9, the restart check.
4. **`aws-up` with an image tag that is not in ECR, or an expired SSO session, must stop before `terraform apply`**, so nothing starts billing for a deploy that cannot work. Test: Task 7, fake-CLI tests.
5. **Anything left billing after destroy must be reported**: EBS volumes from claims, a load balancer, instances, or ENIs. The sweep exits non-zero. Test: Task 5, fake-CLI tests.

**Files:**

**Interfaces:**
- Consumes: `dump_bucket` (base), the cluster from Task 5.
- Produces:
  - A Pod Identity association: namespace `default`, service account `postgres`, a role allowing `s3:GetObject` on `arn:aws:s3:::<dump bucket>/dumps/*`, plus `s3:ListBucket` on the bucket. Without `ListBucket`, a missing object answers 403, not 404.
  - The marker file `/var/lib/postgresql/data/restore-done`, at the volume root, outside `PGDATA`.

The restore rules, which this task's code must follow exactly. They are what make Review Focus 1–3 hold:

- **`fetch-dump`** (the aws-cli image, mounts the data volume at `/data` and an `emptyDir` at `/restore`):
  1. If `/data/restore-done` exists, print "already restored or started fresh" and exit 0. This is a restart of a live database.
  2. Otherwise `rm -rf /data/pgdata`. Whatever is there is from an attempt that never finished.
  3. `aws s3api head-object --bucket $BUCKET --key $KEY`:
     - Not found (`404`) means print "no dump; starting empty" and exit 0.
     - Any other failure means print the error and exit 1. The pod retries and never starts empty.
  4. `aws s3 cp` to `/restore/latest.dump` and exit 0.
- **`10-restore.sh`** (runs once, from `/docker-entrypoint-initdb.d`, inside the Postgres container): `set -e`. If `/restore/latest.dump` is non-empty, run `pg_restore --exit-on-error --no-owner --role=sportsnotifier -U sportsnotifier -d sportsnotifier /restore/latest.dump`. Then, and only then, `touch /var/lib/postgresql/data/restore-done`.
  - A failed restore therefore leaves no marker. The next start wipes and tries again (rule 2), and never serves an empty database.
