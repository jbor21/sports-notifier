# Phase 3b: New UI (Sideline) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app, Sideline, in `web/`, built to `docs/api/` and served by the gateway from the same image, with live scores, notifications, follows, and an installable PWA, checked end to end in CI.

**Architecture:** Vite + React SPA. Plain-TypeScript core (`src/api/`, `src/live/`) holds the HTTP client, the socket's reconnect rules, the version-checked game store, the badge, and pushed notifications; screens read it through hooks. A Dockerfile stage builds `web/dist` into `/app/web`; the gateway's `WebFiles` serves it at `/` with an `index.html` fallback, cache headers, and a host-scoped CSP.

**Tech Stack:** Vite, React 19, TypeScript (strict), React Router, SWR, lucide-react, @fontsource-variable (DM Sans, Manrope), vite-plugin-pwa (injectManifest) + Workbox, openapi-typescript, Vitest + Testing Library (jsdom), Playwright, Prettier, @stoplight/prism-cli, pnpm, Node 24. Java side: Javalin 6.1.6, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-10-08-phase-3b-ui-design.md` (read it with this plan; section numbers below refer to it).

## Global Constraints

- Frontend only: no database, auth, or server code in `web/` (dev-only scripts and test servers are tooling, not shipped).
- The contract is `docs/api/` on main. Types are generated from `docs/api/openapi.yaml` into `web/src/api/schema.d.ts`; never edit that file by hand.
- Alert switches come from `GET /leagues/{id}/alerts`; `coming_soon` → disabled. No hard-coded list of alert types except the spec's answering types (5.5).
- Unknown socket message types and unknown alert types are skipped; an unknown game status renders like `in_progress`.
- Socket: ping every 25 s, and at once when the tab becomes visible while open; 4401 → sign in, no retry; 4000 → retry after 0–1 s jitter; everything else → backoff 1, 2, 4, 8, 16, 30 s (cap 30) + 0–1 s jitter; reset after 60 s open; retry at once on `online` or becoming visible while waiting; after a reconnect re-send `subscribe_games` and refetch.
- A `game_update` or HTTP copy with `version` ≤ the one held is dropped.
- Clocks never tick locally. Times show in `/me`'s `timezone`.
- Base URL `VITE_API_BASE`, default `/api/v1`. The app always calls its own origin; `pnpm dev:mock` proxies to Prism.
- Every screen requires sign-in; any 401 except from `POST /auth/login`, or close 4401, → `/signin?next=<path>`.
- Live look: digits slide in, card ring, "+N" chip for 4 s; reconnect banner after 10 s; animations off under `prefers-reduced-motion`.
- Copy from v0 is kept; the demo mode is not.
- Prettier formats everything in `web/` (except `src/api/schema.d.ts`); CI runs `pnpm format:check`.
- Java: match the existing comment density; config through env vars with defaults (`WEB_DIR`, default `/app/web`).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Session expiry while on `/signin`:** the sign-in screen's own `GET /me` answering 401 must not redirect again (no loop), and `next` must survive. Test in Task 6.
2. **User timezone ≠ browser timezone near midnight:** at `2026-10-08T02:00:00Z` with the browser in UTC and the user in `America/Los_Angeles`, today is `2026-10-07` and the strip is `2026-10-06` … `2026-10-14`. Test in Task 7.
3. **A tab left open across midnight:** Game day's "today" must move when the date changes in the user's timezone (re-derived on each minute tick), not stay on the day the tab opened. Test in Task 7.
4. **A burst of pushes:** ten notifications in a second show at most 3 toasts, newest on top, and all ten are in history. Test in Task 6.
5. **Double click on Follow:** the button is disabled while its `POST /follows` is in flight, so one click → one request. Test in Task 8.

**Interfaces:**
- Produces: `public final class WebFiles { public static boolean register(Javalin app, Path webDir) }`: returns `false` (and logs `[Gateway] no web files at <dir>; serving the API only`) when `webDir/index.html` doesn't exist; otherwise registers and returns `true`. Also `static String contentSecurityPolicy(String hostHeader)` (package-private, tested directly).

All serving goes through one `app.error(404, ...)` handler, so Javalin's routes and their own 404s are untouched. The handler acts only when **all** hold: method `GET`; path not starting with `/api/`; path not `/health`. Then:
1. Resolve `webDir.resolve(path without leading "/").normalize()`; if it is outside `webDir`, leave the 404.
2. A regular file there → serve it, status 200, `Content-Type` by extension (`html`, `js`, `css`, `svg`, `png`, `ico`, `json`, `webmanifest` = `application/manifest+json`, `woff2`, `txt`; else `application/octet-stream`).
3. Else, the last path segment has no `.` (an app route, including `/`) → serve `index.html`, status 200.
4. Else leave the 404.
Headers on every response it serves: `Cache-Control` = `public, max-age=31536000, immutable` when the path starts with `/assets/`, else `no-cache`; `Content-Security-Policy` = `contentSecurityPolicy(ctx.header("Host"))`; `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`.

`contentSecurityPolicy(host)` returns exactly (spec 4.2, `<host>` replaced; when `host` is null or doesn't match `^[A-Za-z0-9.-]+(:[0-9]{1,5})?$`, the `connect-src` is `'self'` alone):
```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: https://a.espncdn.com; font-src 'self'; connect-src 'self' ws://<host> wss://<host>; manifest-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

**Interfaces:**

- Produces:
```ts
export type ConnectionState = 'connecting' | 'open' | 'waiting' | 'signedOut' | 'stopped'
export interface SocketLike {
  readyState: number
  send(data: string): void
  close(code?: number, reason?: string): void
  onopen: (() => void) | null
  onmessage: ((e: { data: string }) => void) | null
  onclose: ((e: { code: number; reason: string }) => void) | null
  onerror: (() => void) | null
}
export interface ConnectionEvents {
  onState(state: ConnectionState, info: { retryAt: number | null; connects: number }): void
  onHello(unreadCount: number): void
  onNotification(n: Notice): void
  onUnreadCount(count: number): void
  onGameUpdate(g: Game): void
  onReconnected(): void
  onSignedOut(): void
}
export function backoffDelay(attempt: number, random: () => number): number
export class LiveConnection {
  constructor(url: string, events: Partial<ConnectionEvents>,
              deps?: { createSocket?: (url: string) => SocketLike; random?: () => number })
  start(): void; stop(): void
  setGames(ids: string[]): void
  retryNow(): void
  readonly state: ConnectionState
  readonly connects: number   // opens so far; > 1 means reconnects happened
}
```
